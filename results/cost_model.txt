WHAT THIS ACTUALLY TELLS YOU
------------------------------------------------------------------------------
  The modelled spend is 3.6% of the stated ceiling. Even if every
  [Assumed] input here is wrong by 5x, the total stays under budget.

  So the $50K/month ceiling is NOT the binding constraint on this design.
  Two dedicated engineers and a three-month MVP window are.

  That inverts a normal build-vs-buy decision. Self-managed Kafka on EC2 is
  cheaper per byte than Kinesis, but it spends the resource that is actually
  scarce: engineer-hours. With 96% of the budget unused, paying AWS list
  price to avoid operating a broker is straightforwardly correct here.

------------------------------------------------------------------------------
WRITE AMPLIFICATION - the number worth arguing about
------------------------------------------------------------------------------
  DynamoDB is 60% of the total, and profile writes alone are
  $938/month, because the model assumes one write per event.

  That assumption is a design choice, not a fact. If the stream job keeps
  per-visitor state and flushes on session end rather than per event, the
  write count drops by roughly the average events-per-session. The cost
  model is what surfaces that: it is not visible from the architecture
  diagram, only from the arithmetic.
